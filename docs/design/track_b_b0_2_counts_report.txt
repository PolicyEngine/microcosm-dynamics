Changes and review findings
  Known ages are integers 1..cohorts.age67._MAX_AGE_CODE. Ages 0, 999,
  fractions and other invalid values enter unknown_age, never an age band
  or R_TA_PROXY. Roster bands plus unknown_age partition persons; the
  youngest band is now 1_24. Tests use the actual named readers on invented
  fixed-width products and hand-count ages 81/125 and 2009 lag origins.
  Integer-bounds recovery and the unpublished co-resident remainder are
  addressed by a complete set registry, membership-signature atoms, and
  every sensitive published-set/subset difference. Wave households have
  separate types; design clusters include stratum. Identical sets and
  objectives share rows/audits. Sparse matrices feed two scipy.optimize.milp
  programs per distinct sensitive quantity, with integer nonnegative atom
  sizes, 60 seconds per program, zero MIP gap and one HiGHS thread. Both
  proven optima and width >=4 are required. No optimum means unprotected.
  Effective sizes supply the specified person/household/design-cluster
  lower bounds. Intermediate rounding was removed before coarsening.
  All counts/effective sizes use halves-up coarsening and the 10/50/100/500
  ladder. If no base passes, only the disclosure block is published. Public
  metadata never names a quantity; sets/memberships are never serialized.
  Unsuppressed counts, atom sizes and audit results go only to the local
  copy. scipy.milp has no initial-solution argument; true atom sizes are
  checked as a feasible witness instead.
  Frozen status and the block pin are mandatory before input resolution.
  An exclusive, fsynced version-specific attempt record holds head, script
  SHA-256 and UTC start time before any PSID file can open. Its name is
  independent of output filenames; the fixed B0.2 evidence folder prevents
  changing the parent directory to bypass the version lock. Existing clean,
  thread, path, symlink and exclusive-output protections remain in place.

Post-build correction (main session, before review round 2)
  count_interval gave a published multiple equal to B the interval
  B/2..3B/2-1. Under the coarsening rule, "B" covers B..3B/2-1, because
  smaller values are written "<B". The effective-size lower bound for a
  published B had the same flaw (B/2 rather than B). Both under-constrained
  the audit, which could then pass a release that an attacker could
  narrow further. Both now start at B.
  The brute-force differential test took its oracle from count_interval,
  so it could not see this; its oracle is now each published value's
  preimage under coarsen, by enumeration. New tests:
  test_count_intervals_are_exact_preimages_of_coarsening (every base in
  the ladder) and test_a_published_base_bounds_its_effective_count_from_base.
  Both fail on the build's code and pass on the fix.
